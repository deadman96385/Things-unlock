    Quick start

    You’ll need a device that supports Android Things authenticated unlock, a valid ZIP or loose credentials for its product, and a computer running Android Platform-Tools.

    Back up your device and check its model-specific unlock instructions before changing the bootloader state.

    Capture the challenge

    Boot the target device into bootloader fastboot mode and connect it by USB. Open PowerShell in the extracted Platform-Tools folder.

    .\fastboot.exe devices
.\fastboot.exe oem at-get-vboot-unlock-challenge
.\fastboot.exe get_staged .\challenge.bin

    If devices lists your target and both commands succeed, add challenge.bin from that folder to the signer above.

    Verify in fastboot

    Move unlock-credential.bin from Downloads into the Platform-Tools folder. Keep the same device in the same bootloader session.

    .\fastboot.exe stage .\unlock-credential.bin
.\fastboot.exe oem at-unlock-vboot
.\fastboot.exe getvar at-vboot-state

    Use the actual filename if your browser adds a suffix. Check for avb-locked: 0. The product ID match in the page only confirms the bundle targets the same product.

    On macOS or Linux, use ./fastboot from Platform-Tools or fastboot on your PATH, and use forward slashes in paths. AOSP command reference

    Troubleshooting

    Fastboot lists no device

    Check the USB data cable, confirm the device is in bootloader fastboot mode, and check the device’s USB driver on Windows. If several devices are listed, disconnect the others or pass the intended serial with -s to every fastboot command.

    Fastboot reports an unknown ATX command

    Confirm you’re in bootloader fastboot mode and check whether your exact model and firmware support Android Things authenticated unlock.

    The page can’t import or match my bundle

    Use the original credential ZIP, or import its PIK certificate, PUK certificate, and matching unencrypted RSA PEM as loose files. If the product ID differs, confirm you captured the challenge from the intended device and use the bundle issued for that product.

    Fastboot rejects the credential or still reports locked

    Capture a fresh challenge from the same device, sign it, and retry in that bootloader session. If it still fails, check your device’s required certificate versions and bootloader support. For a bug report, share the exact model, firmware, Platform-Tools version, and a redacted fastboot error. Keep keys, credential archives, and device serials private.
